1.0.2 - Данные на реальной машине: переписан слой получения состояний.
        Причина молчаливой пустоты - приложение звало одну функцию
        WNApplicationTagHelper.getTagIntervals, которую не использует ни один
        рабочий пример этой установки, и при этом getProduct не читал
        ProductUUID/PersistInfo__idA2, то есть запасной путь к коннектору был
        недоступен в принципе.
        Теперь: состояния берутся четырьмя способами по порядку
        (getSimpleTagIntervalCalculation, getTagIntervalCalculation - как в
        SSONUMBERLOAD, getTagIntervals, WNConnectorHelper.getSignal с
        <appid>.<tid>.SCHED_PRIO.HOUR - как в OEE и ККЗ-КАПО), рабочий способ
        определяется автоматически при загрузке и печатается в консоль;
        список тегов читается из 45_EQUIPMENT_TAG_PRIORITY через
        getApplicationTag (именно оттуда берут теги рабочие приложения),
        подбор по имени остался как дополнение; getProduct читает ProductUUID
        и числовой id изделия; даты во всех запросах с миллисекундами.
        Значения, собранные по часовым корзинам, помечаются в матрице знаком
        «*» и сноской в сводном показателе - точность до часа.
        mode=демо выключен (USE_SAMPLE_DATA=false), настройки источника вынесены
        в manifest.json в медиа-библиотеке (appid, use_sample_data, debug,
        списки тегов) и перекрывают константы manifest.js.
        Добавлены офлайн-проверки: tools/smoke_test.mjs (прогон логики с
        подставным SDK) и сверка каждого вызова SDK в tools/validate_export.mjs.
        Пакет export.zip пересобран. 28.10.2026

1.0.3 - Реализованы Приложения 2 и 3 ТЗ, исправлены высота строк и макет.
        1) Высота строк матрицы больше не зависит от числа станков: платформа
           задаёт элементу «Таблица» фиксированную высоту, и браузер растягивал
           строки под неё. Код переносит позиционирование и высоту на контейнер
           прокрутки (.vpo-scroll), таблица остаётся естественной высоты,
           строки фиксированы (38 px), шапка прижата к верху (position: sticky).
        2) Приложение 2 - выгрузка за длительный период: вместо одной даты два
           поля «запрашиваемый период с ... по ...» (до 92 суток), каждое окно
           обеда рисуется полосами по суткам, сводный показатель считает проценты
           по всему периоду, в Excel добавлен лист «станок x сутки».
           Одна сутки - частный случай того же кода (Приложение 1).
        3) Приложение 3 - каскад выбора объекта: уровни КнААЗ -> производство ->
           цех -> участок собираются по цепочке родительских папок
           WNFolderHelper.getParent (так же делает рабочее приложение «OEE завод
           v10.0.0 с фильтрами»), каждый следующий список зависит от выбранного
           выше, выбор переопрашивает состояния без перезагрузки страницы. Если
           папки не отдают иерархию, остаётся прежний одиночный список по участку.
           Всего станков в выборке больше 80 - берутся первые и над матрицей
           появляется предупреждение.
        4) Макет: сводный показатель перенесён с нижнего яруса в правую колонку
           рядом с матрицей, графики увеличены (высота 150 px, ширина столбца
           46 px) и подписаны осью 0/50/100.
        Прогон tools/smoke_test.mjs дополнен сценариями периода, каскада и
        отдачи без иерархии папок; tools/validate_export.mjs проверяет, что свод
        справа от матрицы, что поле «Данные» короче лимита редактора и что
        классы новой разметки описаны в style.css. 30.10.2026

1.0.4 - Выбор объекта переделан: вместо нескольких списков рядом (по одному на
        уровень) - ОДИН выпадающий список с динамическим деревом папок внутри,
        как в Приложении 3: раскрываешь завод -> видишь его отделы, раскрываешь
        отдел -> цеха, и т.д.
        1) Дерево собирается двумя вызовами SDK, проверенными по руководствам:
           WNFolderHelper.getFolders(org_oid) - все папки организации разом, с
           типом уровня (TypeInfo__internalName: WNPlant1/WNSection1/
           WNShopfloor1/WNPlantBay1) - WN6.0.0 Javascript SDK p.14 и WN5.5.4
           REST API Guide (men=getFolders); WNFolderHelper.getParent(папка) -
           родитель листовой папки станка (FolderInfo__idA6 из getProduct), тем
           же путём идёт «OEE завод v10.0.0 с фильтрами». oid организации
           берётся из OrganizationInfo__idA3, родители кэшируются.
        2) Подпись уровня берётся из типа папки (FOLDER_TYPE_LABELS), а не из
           глубины; против узла - число станков в нём и во всех ветвях ниже;
           выбор узла фильтрует матрицу по всему поддереву.
        3) Панель дерева вешается на document.body (position:fixed, z-index
           9999), иначе держатель платформы с overflow:hidden обрезал её
           нижние уровни. Закрытие - клик вне, Escape, повторное нажатие.
        4) Настройки в manifest.json: use_folder_tree, org_oid (если id
           организации не читается из изделий), folder_type_labels,
           level_labels. Деградация сохранена: без ответов папок - дерево из
           имён участков, use_folder_tree=false - прежний одиночный список.
        Прогон tools/smoke_test.mjs переписан под дерево (прогрессивное
        раскрытие, отступы ветвей, счётчики, выбор, закрытие по клику вне,
        подписи уровней и когда тип папки не ответит) - 57 проверок;
        validate_export.mjs сверяет getFolders/getParent с
        руководствами и новые классы vpo-tree-* со стилями. 30.10.2026
